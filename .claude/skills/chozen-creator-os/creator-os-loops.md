# The Seven Core Execution Loops

Part of [[chozen-creator-os]]. Cards that invoke these: [[creator-os-mission-card]].

A loop is a repeatable workflow that produces a deliverable. Run the steps in order. Each loop can be
run manually today and automated later — that automation is what the future ChoZen OS software exists to do.

## Offer Validation Loop
Use when: an offer, price, or promise is unproven.
1. Define the buyer.
2. Name the painful problem.
3. State the promised result.
4. Show the mechanism.
5. Present the price.
6. Ask for the sale.
7. Record objections — in the customer's exact words, not rewritten into marketing language.
8. Refine one variable. One. Then re-run.

## Digital Product Build Loop
Use when: building a paid or free digital product.
1. Choose one customer result.
2. Outline the minimum deliverables.
3. Build the quick-start path.
4. Produce one complete example.
5. Package files.
6. Test as a customer — actually buy it, actually download it.
7. Correct friction.
8. Publish.

## Content-to-Revenue Loop
Use when: creating content that must connect to money.
1. Choose one customer tension.
2. Teach one clear idea.
3. Show proof or demonstration.
4. Create one primary post.
5. Repurpose into stories/email.
6. Send to one offer — one, not a menu.
7. Follow up personally.
8. Record revenue.

## Product Launch Loop
Use when: opening sales on anything.
1. Confirm product readiness.
2. Set launch goal.
3. Build landing page.
4. Connect checkout.
5. Connect delivery.
6. Create launch content.
7. Open sales.
8. Follow up.
9. Close.
10. Review.

## Customer Feedback Loop
Use when: conversion is unexplained or objections repeat.
1. Ask one focused question.
2. Capture exact language.
3. Categorize the objection (unclear value, wrong audience, no urgency, no trust, price resistance,
   product confusion, technical friction, no perceived need).
4. Identify the repeated pattern.
5. Choose one correction.
6. Implement.
7. Re-test.
8. Document.

## Apparel Drop Loop
Use when: releasing a ChoZen Collection product.
1. Select one hero product.
2. Set quantity ceiling.
3. Confirm manufacturing.
4. Create PDP assets — imagery per colorway.
5. Build waitlist.
6. Open preorder/drop. (Capped drop = small stock + inventoryPolicy DENY; open/made-to-demand =
   0 stock + CONTINUE. Customers are charged at checkout, so the description must state the ship window.)
7. Fulfill.
8. Collect customer proof.

## Founder Health Continuity Loop
Use when: any task or promise depends on the founder being present and well.
1. Identify health-sensitive tasks.
2. Remove live dependence.
3. Pre-record or automate.
4. Document handoff.
5. Assign backup.
6. Test the absence scenario — actually run a day without the founder.
7. Review monthly.

**Continuity standard:** a product is not fully operational until a customer can purchase, receive,
understand, and use it without the founder being present.
